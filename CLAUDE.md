# CLAUDE.md

Правила работы с этим репозиторием. Читаются перед любой правкой вёрстки.

## Что это за проект

Статическая вёрстка сайта студии интерьерного дизайна Perkura: чистый HTML + CSS,
без сборки, фреймворков и зависимостей. Публикуется на GitHub Pages из ветки `main`,
корень репозитория. Что закоммичено — то и опубликовано.

Настоящая главная сайта — `home.html`. Файл `index.html` в корне — служебное
оглавление для заказчика, не главная страница.

**Это этап статики, и содержимое в нём — сознательная рыба.** Дальше будет
бэкенд, и тексты, кейсы, проекты и публикации станут заводиться и обновляться
там. Поэтому рыботекст, одинаковые снимки в ленте, девять карточек портфолио
на одну `project.html` и формы без обработчиков — не долг и не недоделки, а
нормальное состояние работы. Придумывать тексты, заводить недостающие
страницы и вешать обработчики по своей инициативе не нужно. Чинить стоит
другое: когда заглушка врёт о самой структуре сайта — как было с меню услуг,
которое вело мимо раздела.

Про единицу `--px`, `--u`, `--vh` и три режима адаптива — в [README.md](README.md),
про грабли и сознательные расхождения с макетом — в [NOTES.md](NOTES.md).

## Дев-сервер

`tools/dev-server.js` — локальный сервер с живым обновлением. Написан на встроенных
модулях Node, без единой зависимости.

```bash
npm run dev                 # порт 3000 + открыть браузер
npm start                   # то же без открытия браузера
node tools/dev-server.js --port 4000 --quiet
```

Флаги: `--port <n>`, `--open`, `--local` (только 127.0.0.1), `--quiet`, `--root <p>`.
Занятый порт сервер обходит сам — берёт следующий свободный и печатает адрес в баннере.

Что он делает:

- **правка `.css`** — стили подменяются на лету, страница не перезагружается,
  прокрутка остаётся на месте. Главное ради чего он и нужен: длинные страницы,
  правка секции в середине не отбрасывает наверх;
- **правка `.html`, `.js`, файла в `assets/`** — страница перезагружается,
  прокрутка восстанавливается через `sessionStorage`;
- **перезапуск сервера** — открытые вкладки переподключаются и обновляются сами;
- **адреса без расширения** — `/home` отдаёт `home.html`;
- **`Cache-Control: no-store`** на всё — браузер не показывает вчерашний CSS;
- **бейдж в правом нижнем углу** — при изменении ширины окна показывает
  `1440 x 900 десктоп` (порог 1200 и 768 — те же, что в медиазапросах),
  при обрыве связи с сервером краснеет;
- **по умолчанию слушает все интерфейсы** — в баннере печатается адрес вида
  `http://192.168.x.x:3000`, по нему вёрстка открывается с телефона в той же сети.
  Windows при первом запуске спросит разрешение брандмауэра; если оно не нужно —
  `npm run dev:local`.

## Правила для агента

**Проверять вёрстку только через дев-сервер, не через `file://`.** Иначе не работают
абсолютные пути и живое обновление, а поведение отличается от GitHub Pages.

**Дев-сервер запускает только человек.** Агент не поднимает его сам — ни в фоне,
ни на нестандартном порту, ни `npm run dev`, ни `node tools/dev-server.js`. Сервер
держит запущенным Роман, обычно на `http://localhost:3000`; агент только ходит на
уже работающий адрес. Если сервер не отвечает — не запускать его самому, а сказать
об этом и попросить Романа поднять (`npm run dev`) и дождаться его ответа.

**Не добавлять зависимости через npm.** `package.json` существует ради строчки
`npm run dev` и не должен обрасти `dependencies`; `node_modules/` в этом репозитории
не появляется, сборки нет. Нужна возможность, которой нет в дев-сервере, — дописать
её в `tools/dev-server.js` встроенными модулями.

Стороннюю библиотеку для сайта класть готовым файлом в `assets/vendor/` и подключать
обычным `<script src>`: так она лежит в репозитории целиком, работает офлайн и
уезжает на GitHub Pages вместе со страницами — без CDN и без сборки. Так подключён
Embla Carousel 8.6.0 (`assets/vendor/embla-carousel.umd.js` и плагин автопрокрутки)
— слайдер первого экрана и карусель проектов в Works на главной. Своё писать
только там, где готового нет.

**Иконку, которая встречается больше двух раз, класть в `assets/icons.svg`**
символом и подключать через `<svg class="…"><use href="assets/icons.svg#id" /></svg>`.
Там уже лежат логотип, стрелка «на северо-восток» и иконки соцсетей. Инлайном
остаётся только то, к чьим внутренностям обращается CSS: правила вроде
`.works__nav-hit` не достают внутрь `<use>`. И помнить: **в комментариях XML
нельзя ставить два дефиса подряд** — упоминание `--ink` внутри `<!-- -->`
роняет разбор всего спрайта, и символы после него молча перестают рисоваться.
Подробности — в [NOTES.md](NOTES.md), раздел «Иконки в спрайте».

**Скрипт живого обновления в HTML руками не вставлять.** Сервер подмешивает
`<script src="/__dev/client.js">` в ответ на лету, файлы на диске не трогает. В
опубликованной на GitHub Pages версии его нет.

**Адаптив проверять на трёх ширинах:** 1920 и 1440 (десктоп), 900 (планшет),
390 (телефон). Первые экраны обязаны занимать ровно окно и ни пикселя больше.

**Первый экран не анимируется ни на одной странице.** Проявляющийся элемент
задерживает отрисовку LCP, и Google Search Console считает это проблемой.
Правило держится устройством движка: спрятанное состояние навешивает
`initReveal()` в `script.js`, и только тем элементам, которые при загрузке
оказались ниже кромки окна. Поэтому новый блок размечается классами
`reveal reveal--media` / `--text` / `--rule` без оглядки на то, попадёт он
в первый экран или нет, — а вот классов у самих первых экранов быть не должно.
Жестов ровно три, четвёртый не заводить. Подробности — в [NOTES.md](NOTES.md),
раздел «Движение».

**Чистить артефакты проверки перед коммитом.** Скриншоты `*.png` в корне,
каталог `.playwright-mcp/` и прочий мусор браузерных MCP удалять до `git commit`,
а не полагаться на `.gitignore`: в репозитории им не место ни в истории, ни на
диске. Проверка проходит так: прогнать браузером, посмотреть результат, удалить
файлы, и только потом коммитить и пушить.

**Стиль сообщений коммитов** — как в истории: по-русски, одной фразой о сути
сделанного, без префиксов вроде `feat:`. Например: «Свёрстана лента новостей:
крупная первая публикация и четыре карточки».

## SEO: что уже стоит и что осталось

Работа велась в четыре захода и остановлена на середине по просьбе Романа.
Что доделывать — ниже; порядок пунктов и есть порядок работ.

### Сделано

- **`noindex, follow`** на `index.html` (служебное оглавление).
- **Разобрана путаница со страницами услуг.** «Услуги» и «Услуги, вариант 2»
  в макете — не два оформления одной страницы, а два уровня одного раздела:
  `services-2.html` — список из четырёх услуг, с него «Подробнее» уводит на
  `services.html`, страницу услуги «интерьер под ключ». Поэтому пункт меню
  «Услуги» на всех восьми страницах ведёт на `services-2.html`, крошки на
  `services.html` доведены до трёх (`Главная` → `Услуги` → `Интерьер под
  ключ`), а `noindex` с `services-2.html` снят — дубля больше нет. Имена
  файлов достались от первого прочтения макета и звучат наоборот; менять их
  без просьбы заказчика не стали.
- **`h1` главной** описывает студию. Надписи слайдов первого экрана — названия
  проектов, поэтому все три набраны `<p>`, а заголовок страницы живёт скрытым
  элементом в начале `.hero`. Прячет его утилита `.visually-hidden` в
  `styles.css` — вырезание рамкой в один пиксель, а не `display: none`:
  от последнего текст пропадает и для экранной читалки.
- **`canonical`** на всех девяти страницах и **`theme-color`** `#171717`
  (цвет шапки).
- **Open Graph и Twitter Card** на всех девяти страницах: тип, название,
  описание, снимок с размерами и `alt`.

### Осталось

**Микроразметка JSON-LD.** Ни на одной странице её нет. Задумано так:
`Organization` и `WebSite` на главной, `Person` (Арина Метелькова) на
`about.html`, `CollectionPage` на `portfolio.html`, `BlogPosting` на
`article.html`, `BreadcrumbList` всюду, где крошки есть в разметке. Комментарии
внутри JSON запрещены — пояснение про заглушки ставится HTML-комментарием перед
`<script type="application/ld+json">`.

**Имена файлов услуг звучат наоборот.** `services.html` — страница одной
услуги, `services-2.html` — раздел. Понятнее было бы `services.html` для
раздела и `service-turnkey.html` для услуги, но это переименование ломает
ссылки, которые заказчик уже мог сохранить. Делать по его слову.

**Крошки на `project.html` разъезжаются со смыслом.** Последняя крошка —
`<a class="breadcrumbs__link breadcrumbs__current" href="portfolio.html">Портфолио</a>`:
ссылка на другую страницу с классом «текущая» и без `aria-current="page"`.
Текущая страница здесь — сам проект. Должно быть: `Главная` → `Портфолио`
(ссылка) → `Modern and Monochrome` (`<span>` с `aria-current="page"`), как
сделано на `article.html`.

**Разнобой в названии раздела проектов.** В меню он «Портфолио», в крошках
`portfolio.html` и в её `h1` — «Проекты», в крошках `project.html` — снова
«Портфолио». Выбрать одно слово и держать его везде: поиск сшивает страницы
в раздел по совпадению названий.

**Крошка `article.html`** гласит «Новость» вместо названия публикации. Для
`BreadcrumbList` последняя крошка должна повторять `h1`.

**Дат у публикаций нет вовсе.** Ни `<time datetime>` в разметке, ни
`article:published_time` в мете — в `article.html` и `project.html` на их месте
стоит комментарий-шаблон. Без даты `BlogPosting` не даёт расширенного сниппета.
Заводить дату — вместе с настоящим текстом, не раньше.

**Описания коротковаты.** 79–106 символов при удобных для выдачи 120–160.
Не ошибка, но место под ключевые слова простаивает.

**Заглушечные ссылки ведут в оглавление.** «Политика конфиденциальности»,
«Правовая информация», «Смотреть все» — все указывают на `index.html`,
который закрыт `noindex`. Пока страниц нет, так и остаётся; как появятся —
переставить. «Подробнее» из блока About us на главной уже переставлено
на `about.html`.

**Английская рыба не помечена `lang="en"`.** Экранная читалка произносит её
по-русски. Помечать сейчас смысла нет: текст всё равно заменят на русский,
и атрибуты придётся снимать.

**Переключатель языков в шапке пока визуальный.** Страниц-переводов нет:
выбор живёт в `localStorage` и ничего не грузит (см. «Переключатель языков»
в NOTES.md). Когда появятся EN/TR-версии — пункты панельки становятся
ссылками, а рядом с `canonical` встаёт `hreflang` вместе с `x-default`.

### Чего сознательно не делаем

- **`robots.txt` и `sitemap.xml`** — сайт не готов, отдавать его поисковику рано.
- **Абсолютные адреса.** Боевого домена нет, поэтому `canonical` относительный,
  а `og:url` не проставлен вовсе. Когда домен появится: `canonical` и `og:image`
  переписываются на полные адреса, рядом с `og:image` встаёт `og:url`. Это
  сквозная правка по всем девяти файлам — искать по `rel="canonical"`.
- **Своей карточки 1200×630** под превью в мессенджерах нет: `og:image` пока
  показывает снимок со страницы.
