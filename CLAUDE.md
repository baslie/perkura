# CLAUDE.md

Правила работы с этим репозиторием. Читаются перед любой правкой вёрстки.

## Что это за проект

Статическая вёрстка сайта студии интерьерного дизайна Perkura: чистый HTML + CSS,
без сборки, фреймворков и зависимостей. Публикуется на GitHub Pages из ветки `main`,
корень репозитория. Что закоммичено — то и опубликовано.

Настоящая главная сайта — `home.html`. Файл `index.html` в корне — служебное
оглавление для заказчика, не главная страница.

Про единицу `--px`, `--u`, `--vh` и три режима адаптива — в [README.md](README.md),
про грабли и сознательные расхождения с макетом — в [NOTES.md](NOTES.md).

## Дев-сервер

`tools/dev-server.js` — локальный сервер с живым обновлением. Написан на встроенных
модулях Node, без единой зависимости.

```bash
npm run dev                 # порт 3000 + открыть браузер
npm start                   # то же без открытия браузера
node tools/dev-server.js --port 4000 --quiet
```

Флаги: `--port <n>`, `--open`, `--local` (только 127.0.0.1), `--quiet`, `--root <p>`.
Занятый порт сервер обходит сам — берёт следующий свободный и печатает адрес в баннере.

Что он делает:

- **правка `.css`** — стили подменяются на лету, страница не перезагружается,
  прокрутка остаётся на месте. Главное ради чего он и нужен: длинные страницы,
  правка секции в середине не отбрасывает наверх;
- **правка `.html`, `.js`, файла в `assets/`** — страница перезагружается,
  прокрутка восстанавливается через `sessionStorage`;
- **перезапуск сервера** — открытые вкладки переподключаются и обновляются сами;
- **адреса без расширения** — `/home` отдаёт `home.html`;
- **`Cache-Control: no-store`** на всё — браузер не показывает вчерашний CSS;
- **бейдж в правом нижнем углу** — при изменении ширины окна показывает
  `1440 x 900 десктоп` (порог 1200 и 768 — те же, что в медиазапросах),
  при обрыве связи с сервером краснеет;
- **по умолчанию слушает все интерфейсы** — в баннере печатается адрес вида
  `http://192.168.x.x:3000`, по нему вёрстка открывается с телефона в той же сети.
  Windows при первом запуске спросит разрешение брандмауэра; если оно не нужно —
  `npm run dev:local`.

## Правила для агента

**Проверять вёрстку только через дев-сервер, не через `file://`.** Иначе не работают
абсолютные пути и живое обновление, а поведение отличается от GitHub Pages.

**Дев-сервер запускает только человек.** Агент не поднимает его сам — ни в фоне,
ни на нестандартном порту, ни `npm run dev`, ни `node tools/dev-server.js`. Сервер
держит запущенным Роман, обычно на `http://localhost:3000`; агент только ходит на
уже работающий адрес. Если сервер не отвечает — не запускать его самому, а сказать
об этом и попросить Романа поднять (`npm run dev`) и дождаться его ответа.

**Не добавлять зависимости через npm.** `package.json` существует ради строчки
`npm run dev` и не должен обрасти `dependencies`; `node_modules/` в этом репозитории
не появляется, сборки нет. Нужна возможность, которой нет в дев-сервере, — дописать
её в `tools/dev-server.js` встроенными модулями.

Стороннюю библиотеку для сайта класть готовым файлом в `assets/vendor/` и подключать
обычным `<script src>`: так она лежит в репозитории целиком, работает офлайн и
уезжает на GitHub Pages вместе со страницами — без CDN и без сборки. Так подключён
Embla Carousel 8.6.0 (`assets/vendor/embla-carousel.umd.js` и плагин автопрокрутки)
— слайдер первого экрана на главной. Своё писать только там, где готового нет.

**Скрипт живого обновления в HTML руками не вставлять.** Сервер подмешивает
`<script src="/__dev/client.js">` в ответ на лету, файлы на диске не трогает. В
опубликованной на GitHub Pages версии его нет.

**Адаптив проверять на трёх ширинах:** 1920 и 1440 (десктоп), 900 (планшет),
390 (телефон). Первые экраны обязаны занимать ровно окно и ни пикселя больше.

**Чистить артефакты проверки перед коммитом.** Скриншоты `*.png` в корне,
каталог `.playwright-mcp/` и прочий мусор браузерных MCP удалять до `git commit`,
а не полагаться на `.gitignore`: в репозитории им не место ни в истории, ни на
диске. Проверка проходит так: прогнать браузером, посмотреть результат, удалить
файлы, и только потом коммитить и пушить.

**Стиль сообщений коммитов** — как в истории: по-русски, одной фразой о сути
сделанного, без префиксов вроде `feat:`. Например: «Свёрстана лента новостей:
крупная первая публикация и четыре карточки».
