# Perkura

Статичная вёрстка сайта студии интерьерного дизайна **Perkura**: чистый HTML +
CSS, без сборки, зависимостей и фреймворков. Публикуется на GitHub Pages.

**Адрес:** https://roman-purtow.ru/perkura/

## Что внутри

В корне лежит `index.html` — служебное оглавление для заказчика: показывает, какие
страницы уже свёрстаны, а какие пока существуют только в макете. Настоящая главная
сайта живёт в `home.html` именно поэтому.

| страница | файл | состояние |
|---|---|---|
| Главная | `home.html` | свёрстана, девять секций |
| Страница проекта | `project.html` | свёрстана, двенадцать секций |
| Портфолио | — | только макет |
| Услуги | — | только макет |
| О нас | — | только макет |
| Новости | — | только макет |
| Новость | — | только макет |

## Структура

```
perkura/
├── index.html     оглавление: сетка страниц и их состояние (служебная страница)
├── home.html      главная сайта
├── project.html   страница проекта
├── styles.css     все стили: сначала десктоп, ниже медиазапросы, в конце оглавление
├── script.js      слайдер первого экрана и меню под бургером
├── assets/        снимки из макета
├── tools/
│   └── dev-server.js   локальный сервер с живым обновлением, без зависимостей
├── package.json   только скрипты запуска, зависимостей нет
├── CLAUDE.md      правила работы с репозиторием
├── NOTES.md       заметки по вёрстке: единица --px, адаптив, расхождения с макетом

```

## Как устроены размеры

Вёрстка full-width: композиция тянется на всю ширину окна и сохраняет пропорции
макета. Опорная ширина — 1920. Чтобы не пересчитывать каждое значение в `vw`
вручную, введена единица `--px` — один пиксель макета:

```css
:root { --px: 0.05208333vw; }   /* 1920 * 0.05208333vw = 100vw */
```

Дальше всё пишется как `calc(1224 * var(--px))` и читается ровно как «1224 в
макете». Ниже 1200 `--px` равен настоящему пикселю.

Адаптив в трёх режимах: ≥ 1200 — десктопная композиция, 768–1199 — планшет
(одна колонка, поля 30), < 768 — телефон (поля 15, меню под бургером).

Первые экраны обеих страниц занимают ровно окно и ни пикселя больше: их высота
считается от `--vh` (`100svh`, где браузер её знает) минус шапка. Композиция
первого экрана главной при этом сжимается в пропорциях макета — за это отвечает
своя единица `--u`, ужатый `--px`.

Подробности, грабли и сознательные расхождения с макетом — в [NOTES.md](NOTES.md).

## Локальный запуск

В репозитории лежит свой дев-сервер с живым обновлением — `tools/dev-server.js`.
Зависимостей у него нет, ставить нечего, нужен только Node 18 или новее.

```bash
npm run dev
```

Сервер поднимется на http://localhost:3000 и откроет браузер. Если порт занят —
возьмёт следующий свободный и напечатает адрес. Без открытия браузера — `npm start`,
на другом порту — `node tools/dev-server.js --port 4000`.

Что даёт живое обновление:

| правка | что происходит |
|---|---|
| `styles.css` | стили подменяются на лету, страница не перезагружается, прокрутка на месте |
| `.html`, `.js`, файл в `assets/` | страница перезагружается и возвращается на прежнюю прокрутку |
| перезапуск сервера | открытые вкладки переподключаются и обновляются сами |

Мелочи, которые экономят время: адрес можно писать без расширения (`/home` вместо
`/home.html`), ответы отдаются с `no-store` — браузер не покажет вчерашний CSS, а при
изменении ширины окна в углу всплывает бейдж `1440 x 900 десктоп`: видно, в каком из
трёх режимов адаптива сейчас страница.

### Посмотреть с телефона

По умолчанию сервер слушает все интерфейсы и печатает в баннере второй адрес:

```
на этой машине     http://localhost:3000
в локальной сети   http://192.168.1.42:3000
```

Второй открывается с телефона в той же сети — удобно проверять телефонный режим на
настоящем телефоне, а не в эмуляции. Windows при первом запуске спросит разрешение
брандмауэра. Если наружу отдавать не нужно — `npm run dev:local`, тогда сервер
слушает только 127.0.0.1.

Дев-сервер — инструмент разработки. На GitHub Pages попадают только статические
файлы: скрипт живого обновления подмешивается в HTML на лету и в репозитории его нет.
